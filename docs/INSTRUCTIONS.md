\# GroupLore — Complete UI/UX Restyling Brief

\## Design Direction: Magazine × Y2K



\### 1. Objective



Completely restyle the existing GroupLore application around a \*\*Magazine × Y2K visual identity\*\*.



Use the attached reference image as the primary design inspiration. Study its typography, spacing, color palette, card treatments, visual hierarchy, decorative elements, and overall composition.



The objective is to make GroupLore feel like a premium, playful, contemporary digital magazine fused with early-2000s Y2K aesthetics.



This should NOT look like:

\- A generic SaaS dashboard.

\- A conventional gaming platform.

\- A neon-heavy cyberpunk interface.

\- A completely minimal, empty interface.

\- A childish cartoon game website.

\- A template-generated AI dashboard.



It should feel like a thoughtfully art-directed product with a recognizable visual identity.



\*\*Core design philosophy: Editorial structure + Y2K personality + Game-like interactions.\*\*



Use editorial magazine design for the structure, Y2K for the visual language, and subtle arcade-inspired details for interactive elements.



\---



\### 2. Important: Understand the Existing Project Before Modifying It



Before writing or changing code:



1\. Explore the complete existing codebase.

2\. Understand the current routing, page structure, components, styling system, and application architecture.

3\. Identify all existing screens, modals, overlays, game interfaces, lobby states, and responsive layouts.

4\. Understand the existing game logic, multiplayer functionality, socket events, state management, and backend integration.

5\. Identify reusable components and existing design tokens.

6\. Map out the complete user journey, from landing/dashboard to creating a group, joining a room, selecting a game, playing, and viewing results.



Do not redesign based solely on the dashboard screenshot.



The screenshot is the visual foundation for the entire application, but every screen must be adapted intelligently to its purpose.



\*\*Critical requirement:\*\* This is a visual and UX restyling project. Preserve the existing functionality and application architecture.



Do not:

\- Remove existing features.

\- Break multiplayer functionality.

\- Change game rules or game mechanics.

\- Modify socket event contracts unnecessarily.

\- Replace working backend functionality with mock data.

\- Remove existing routes or user flows.

\- Simplify complex game interfaces merely to make them visually easier to design.



The final application must remain fully functional.



\---



\### 3. Overall Visual Identity



\#### Design Direction



\*\*Magazine × Y2K\*\*



The design should combine:



\- Editorial magazine layouts.

\- Oversized, expressive typography.

\- Asymmetric compositions.

\- Layered content sections.

\- Strong typographic hierarchy.

\- Soft paper-like backgrounds.

\- Chrome and metallic accents.

\- Playful geometric decorations.

\- Bold, colorful game cards.

\- Carefully controlled visual textures.



The interface should have personality without becoming visually exhausting.



\#### Visual Balance



Follow this approximate balance:



\- 65% Editorial magazine structure.

\- 25% Y2K visual elements.

\- 10% Arcade-inspired interaction details.



The interface must remain usable and readable even when decorative elements are present.



Avoid filling every empty space with stickers, shapes, icons, or illustrations.



\*\*Important: Do not minimalize the design. Reduce clutter, not personality.\*\*



\---



\### 4. Color System



Establish a consistent design token system.



Use the following palette as the foundation:



| Purpose | Color |

|---|---|

| Primary background | Warm cream `#F8F1E7` |

| Secondary background | Soft ivory `#FFF9F0` |

| Primary text | Near black `#171717` |

| Secondary text | Muted charcoal `#66615F` |

| Primary accent | Lavender `#BFA0F4` |

| Secondary accent | Electric lime `#D7F45B` |

| Tertiary accent | Soft pink `#F29BCB` |

| Cool accent | Muted cyan `#8EDCEB` |

| Borders | Warm grey `#D8D0C5` |

| Chrome highlight | Silver gradient |



\#### Color Usage Rules



\- Cream and ivory should dominate the overall application.

\- Black should provide contrast and typography.

\- Lavender should be the primary brand accent.

\- Lime should be used for primary actions and important highlights.

\- Pink and cyan should provide variation across games and secondary sections.

\- Metallic silver should be used sparingly for decorative Y2K details.



Avoid excessive gradients.



Avoid using all accent colors in every component.



Each screen should have a controlled palette with one dominant accent and supporting colors.



Dark mode must have its own carefully designed palette rather than simply inverting the light theme.



\---



\### 5. Typography



Typography is one of the most important parts of this direction.



Create a strong editorial hierarchy.



Suggested font system:



\*\*Display / Headings\*\*

\- Archivo Black

\- Space Grotesk

\- Satoshi or a similar geometric display typeface.



\*\*Body\*\*

\- DM Sans

\- Inter



\*\*Labels / Metadata\*\*

\- Space Mono



Use typography intentionally.



Examples:

\- Large, bold headlines for page titles.

\- Italicized editorial subheadings.

\- Monospaced uppercase labels for categories and metadata.

\- Compact text for secondary information.

\- Strong weight contrast between headings and descriptions.



Use oversized typography where appropriate, but do not let headings compromise usability.



Avoid using too many different font families.



\---



\### 6. Layout Language



Adopt a magazine-inspired layout system.



Use:



\- Strong section headings.

\- Editorial dividers.

\- Asymmetric content arrangements.

\- Large hero sections.

\- Carefully layered cards.

\- Distinct content blocks.

\- Generous but purposeful spacing.

\- Clear separation between navigation, content, and supporting information.



Avoid making every page look like the same grid of rounded cards.



Different pages should have different compositions while sharing a consistent design language.



Use a consistent spacing scale and responsive layout system.



\#### Borders and Surfaces



\- Prefer thin, warm-grey borders.

\- Use moderate corner radii.

\- Use subtle shadows rather than heavy elevation.

\- Introduce occasional offset borders or layered surfaces.

\- Use paper-like textures sparingly.

\- Avoid excessive glassmorphism.



The interface should feel tactile and editorial, not glossy everywhere.



\---



\### 7. Y2K Visual Elements



Introduce Y2K details as controlled visual accents.



Possible elements:



\- Chrome or metallic 3D stars.

\- Small glossy geometric objects.

\- Retro-inspired gradients.

\- Subtle checkerboard patterns.

\- Abstract wireframe graphics.

\- Small sparkles.

\- Organic abstract shapes.

\- Metallic typography accents.

\- Retro computer-inspired decorative details.

\- Small sticker-like labels.



Use these selectively.



The reference image demonstrates the intended balance: a recognizable decorative focal point, a few supporting accents, and enough whitespace for the content to breathe.



\*\*Do not reproduce the exact same star, shapes, or decorations across every screen.\*\*



Create a small visual asset language that can be reused without making the application repetitive.

\### 8. Dashboard



Use the attached reference image as the closest representation of the intended dashboard.



The dashboard should contain:



\- A clear navigation sidebar.

\- GroupLore branding.

\- Search and profile controls.

\- A large editorial hero section.

\- A prominent Play Now action.

\- Your Groups section.

\- Featured Games section.

\- Recent activity.

\- Group creation action.



\#### Hero Section



Make the hero the main visual anchor.



Use:

\- Large GroupLore branding.

\- A bold editorial headline.

\- A short description.

\- A prominent lime CTA.

\- One or two supporting Y2K visual elements.



Avoid large photographs or collages of multiple people.



The design should rely more on typography, shapes, and controlled visual compositions than photography.



\#### Featured Games



Create expressive game cards with:

\- Unique accent colors.

\- Large game titles.

\- Short descriptions.

\- Player-count information.

\- Small, purposeful illustrations or graphic objects.

\- Clear interaction affordances.



Cards should feel like magazine covers or editorial feature tiles.



Do not make them look like generic SaaS feature cards.

\### 9. Groups and Social Experience



GroupLore revolves around friend groups and their shared context.



The UI should reflect this social personality.



Restyle:

\- Group listings.

\- Group details.

\- Group creation.

\- Group invitations.

\- Member lists.

\- Group settings.

\- Group activity.

\- Group-specific game history.



Use:

\- Editorial group headers.

\- Color-coded group identities.

\- Compact member representations.

\- Playful status labels.

\- Clear group actions.

\- Distinct sections for group information and activity.

Use avatars where they genuinely help identify players, not as decorative filler.

\### 10. Lobby and Multiplayer Room



The lobby is an important part of the experience.



It should feel like a social gathering space rather than an administrative waiting room.



Redesign:

\- Room code display.

\- Player list.

\- Host controls.

\- Game selection.

\- Ready states.

\- Invite and share actions.

\- Lobby status.

\- Game settings.

\- Start game interaction.



Visual direction:

\- A strong room title.

\- A distinct group identity.

\- Clear player slots.

\- Playful ready indicators.

\- A visually prominent Start Game button.

\- Game selection presented through editorial game cards.



Use subtle motion and feedback to make player joins, leaves, and ready-state changes feel alive.



Preserve real-time synchronization and all existing lobby functionality.



\---



\### 11. Individual Game Interfaces



This is the most important part of the redesign after the dashboard.



Every game should feel like a distinct experience while still belonging to GroupLore.



Do not force every game into an identical interface.



Create a shared game design system with reusable elements:



\- Game header.

\- Round indicator.

\- Timer.

\- Player information.

\- Question or prompt container.

\- Answer controls.

\- Voting interface.

\- Scoreboard.

\- Progress indicators.

\- Results and reveal states.

\- Host controls.



Then adapt these elements to each game's requirements.



\#### Game-Specific Visual Personalities



Examples:



| Game | Visual Direction |

|---|---|

| Most Likely To | Editorial poll / magazine voting |

| Guess the Impostor | Investigation / dossier aesthetic |

| 5 Second Challenge | Bold countdown / arcade typography |

| Overrated or Underrated | Rating cards / editorial review |

| Higher or Lower | Comparison / quiz-show layout |

| Would You Rather | Split editorial composition |

| Wavelength | Scale-based visual interaction |

| Caption This | Image-led editorial layout |

| Hot Takes | Bold opinion / debate layout |

| Two Truths One Lie | Mystery / reveal layout |

| Category Rush | Fast-paced typographic challenge |

| Odd One Out | Pattern and comparison layout |

| Roast Battle | Competitive editorial face-off |



These are design suggestions, not instructions to alter gameplay.



Each game should have its own controlled accent color, supporting graphic treatment, and layout identity.



Maintain consistent navigation, typography, buttons, controls, and overall design language across all games.



\#### Gameplay Readability



Gameplay screens must prioritize:

1\. Understanding the current task.

2\. Seeing the relevant information.

3\. Interacting with the game.

4\. Understanding progress and feedback.



Do not let decorative elements compete with actual gameplay.



Use visual effects only when they support an interaction or game event.

Restyle:

\- Round results.

\- Final standings.

\- Winner announcements.

\- Player statistics.

\- Voting breakdowns.

\- Game summaries.

\- Rematch actions.

\- Return-to-lobby actions.



Use:

\- Large editorial result headlines.

\- Strong numerical typography.

\- Controlled accent colors.

\- Distinct winner treatments.

\- Playful but restrained celebratory effects.

\- Clear next-step actions.



Avoid generic trophy-heavy gaming UI.



Make the results feel like the final page of a magazine feature.

\### 13. Interaction Design and Motion



Use Framer Motion where appropriate.



Interactions should feel responsive, tactile, and slightly playful.



Examples:

\- Subtle hover elevation on cards.

\- Small rotations on selected interactive elements.

\- Smooth section transitions.

\- Animated button feedback.

\- Gentle reveal animations.

\- Score and countdown transitions.

\- Smooth modal entrances.

\- Subtle player join/leave animations.



Use motion intentionally.



Avoid:

\- Excessive bouncing.

\- Constant floating decorations.

\- Long transitions.

\- Unnecessary parallax.

\- Animation that interferes with gameplay.

\- Motion on every single component.



Respect reduced-motion preferences.

\### 14. Buttons, Inputs, and Components



Create a cohesive component system.



\#### Buttons

\- Primary: black text on lime.

\- Secondary: black or cream with a thin border.

\- Tertiary: text-based editorial action.

\- Destructive: restrained red treatment.



Use clear hover, active, disabled, and loading states.



\#### Inputs

\- Warm neutral backgrounds.

\- Thin borders.

\- Strong focus indicators.

\- Clear labels.

\- Consistent sizing.



\#### Cards

\- Moderate corner radii.

\- Thin borders.

\- Controlled shadows.

\- Distinct accent treatments.

\- Purposeful hover interactions.



\#### Modals and Popovers

\- Editorial typography.

\- Clear visual hierarchy.

\- Restrained surfaces.

\- Strong action placement.



Every component must look like it belongs to the same design system.

\### 16. Responsive Design



The entire application must work across:



\- Desktop.

\- Laptop.

\- Tablet.

\- Mobile.



Do not treat mobile as an afterthought.



\#### Desktop

\- Magazine-style compositions.

\- Sidebar navigation where appropriate.

\- Multiple content columns.

\- Large editorial hero sections.



\#### Tablet

\- Adjusted grid layouts.

\- Reduced decorative elements.

\- More compact navigation.

\- Preserved content hierarchy.



\#### Mobile

\- Single-column content flow.

\- Appropriate mobile navigation.

\- Readable typography.

\- Touch-friendly controls.

\- Compact game interfaces.

\- No horizontal overflow.

\- No clipped content.

\- No overlapping decorative elements.



Multiplayer game interfaces must remain comfortable to use on mobile screens.

\### 17. Design System and Implementation



Build the design as a reusable system rather than styling every page independently.



Create or update:

\- Global design tokens.

\- Typography variables.

\- Color variables.

\- Spacing variables.

\- Border and radius tokens.

\- Shared button components.

\- Shared card components.

\- Navigation components.

\- Game interface components.

\- Modal and overlay components.

\- Light and dark theme definitions.



Use the existing project architecture and styling conventions wherever possible.



Keep components modular and maintainable.



Avoid:

\- Duplicated styling.

\- Excessive one-off CSS.

\- Arbitrary inline styles.

\- Inconsistent spacing.

\- Hardcoded colors scattered throughout the codebase.

\- Unnecessary dependencies.



Use the existing stack and installed dependencies unless there is a compelling technical reason to change something.

\### 18. Execution Strategy



Implement the redesign in logical stages:



\*\*Phase 1: Audit\*\*

\- Explore the complete application.

\- Identify all screens and reusable components.

\- Document the existing architecture and functionality.

\- Identify visual inconsistencies.



\*\*Phase 2: Foundation\*\*

\- Establish the new color system.

\- Establish typography.

\- Create spacing, surface, border, and shadow tokens.

\- Implement light and dark themes.

\- Create shared UI primitives.



\*\*Phase 3: Main Application\*\*

\- Redesign dashboard.

\- Redesign navigation.

\- Redesign groups and group details.

\- Redesign account and settings screens.



\*\*Phase 4: Multiplayer Experience\*\*

\- Redesign room creation and joining.

\- Redesign lobby.

\- Redesign game selection.

\- Redesign player and host controls.



\*\*Phase 5: Game Interfaces\*\*

\- Restyle every existing game.

\- Preserve game-specific layouts and interactions.

\- Establish consistent game components.

\- Implement distinct visual identities for individual games.



\*\*Phase 6: Results\*\*

\- Redesign scoreboards.

\- Redesign results.

\- Redesign winner and reveal states.

\- Redesign rematch and return flows.



\*\*Phase 7: Responsive and Polish\*\*

\- Test desktop, tablet, and mobile.

\- Test light and dark themes.

\- Fix layout issues.

\- Refine spacing and typography.

\- Refine transitions and interactions.

\- Remove visual inconsistencies.

\### 19. Quality Standards



The final application must satisfy these requirements:



\- Every existing screen has been considered and restyled.

\- All existing functionality continues to work.

\- All existing games retain their original mechanics.

\- Multiplayer interactions remain functional.

\- The design language is consistent across the product.

\- Individual games have distinct visual personalities.

\- Light and dark modes are complete.

\- Mobile layouts are properly implemented.

\- No broken layouts or overlapping components.

\- No excessive decorative elements.

\- No generic SaaS styling.

\- No unnecessary visual minimalism.

\- No placeholder functionality replacing real features.



Before finishing, inspect the actual rendered application rather than relying exclusively on code review.



Test the main user journeys and fix any visual or functional regressions introduced by the redesign.



\---



\### 20. Final Creative Direction



The most important instruction:



\*\*Make GroupLore look like a beautifully art-directed Y2K editorial magazine that happens to be an interactive multiplayer gaming platform.\*\*



It should be expressive, colorful, slightly nostalgic, social, playful, and visually distinctive.



Keep the interface rich enough to have character, but controlled enough that users can comfortably spend an entire game night inside it.



Use the attached reference image as the visual north star, not as a rigid template.



Preserve the personality. Reduce unnecessary clutter. Do not minimalize the experience.



The final result should look like one cohesive, intentionally designed product from the dashboard all the way through the last game result screen.
